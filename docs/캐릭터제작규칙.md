# 캐릭터 제작 규칙 (Character Creation Rules)

> **목적**: PLEPA 엔진에서 체크포인트 모델 간 일관성 있는 고품질 이미지 생성을 보장하기 위한 캐릭터 JSON 작성 가이드

## 1. 필수 구조

### 1.1 기본 필드
```json
{
  "prefix": "캐릭터ID (영문, 파일명 접두사)",
  "name": "캐릭터 이름 (한글/영문)",
  "gender": "female 또는 male",
  "appearance": { ... },
  "sdxl_positive": "SDXL 엔진 전용 positive 프롬프트",
  "sdxl_negative": "SDXL 엔진 전용 negative 프롬프트",
  "ref_weight": 0.75
}
```

### 1.2 SDXL 필드 필수화
- **반드시 `sdxl_positive`와 `sdxl_negative` 필드를 포함해야 함**
- `appearance` 필드는 레거시 호환용으로 유지 가능하지만, SDXL 생성 시 `sdxl_positive`가 우선 사용됨
- `style_keywords` 같은 별도 필드는 사용하지 않음 (엔진별 필드에 통합)

---

## 2. Positive 프롬프트 작성 규칙

### 2.1 구조 (BREAK로 구분)
```
[퀄리티 태그] BREAK [캐릭터 기본 정보] BREAK [외모 상세] BREAK [의상 상세]
```

**예시:**
```
masterpiece, best quality, newest, absurdres, aesthetic illustration, delicate anime coloring, soft shaded skin, finely detailed beautiful eyes BREAK 
1girl, solo, mature female, 29yo, slender waist, soft feminine curves, graceful posture BREAK 
dark chestnut brown hair in neat ponytail, luminous warm amber eyes, refined facial features, clean pale skin BREAK 
pristine fitted white blouse, beige tailored jacket, matching pleated short skirt
```

### 2.2 퀄리티 태그 (필수)
- `masterpiece, best quality, newest, absurdres`
- `aesthetic illustration` (일러스트 스타일 강조)
- `delicate anime coloring, soft shaded skin` (애니메이션 질감)
- `finely detailed beautiful eyes` (눈 디테일 강조)

### 2.3 색상 표현 주의사항
#### ❌ 피해야 할 표현
- `healthy skin tone` ← 모호함, Illustrious 계열 모델에서 주황빛으로 오해석
- `warm skin` ← WAI/HEXMIX에서 과도하게 주황색으로 렌더링
- `rosy skin` ← 피부 전체가 붉어질 수 있음
- `flushed skin`, `heavy blush` ← 얼굴 전체가 주황색/빨간색으로 물듦
- `gentle pink flush` ← WAI에서 과도하게 쨍한 색감으로 렌더링
- `soft blush, rosy cheeks, gentle pink flush` ← 중복된 블러시 표현 (과포화)

#### ✅ 권장 표현
- `clean pale skin` ← 명확하고 중립적
- `fair skin` ← 밝은 피부 (주황빛 없음)
- `smooth skin` ← 질감 강조, 색상 중립적
- `light blush, rosy cheeks` ← 볼터치만 적당히 (중복 없이 단일 표현)

### 2.4 배경/환경 표현 주의사항
#### ❌ 피해야 할 표현
- `pool` (in liquid context) ← Illustrious 계열에서 실제 물웅덩이/수영장으로 오해석, 초록 배경 생성
- `pond`, `lake` ← 마찬가지로 물 배경으로 렌더링

#### ✅ 권장 표현
- `puddle` ← 작은 웅덩이/얼룩 (액체 맥락에서)
- `stain` ← 얼룩/자국
- 예: `cum pool` (❌) → `cum puddle, cum stain` (✅)

### 2.5 가중치 사용
- 중요한 특징은 `(표현:1.2)` ~ `(표현:1.35)` 범위로 강조
- 색상 고정이 필요하면 `((solid black hair:1.35))` 처럼 이중 괄호 + 높은 가중치
- 부정적 표현 배제는 negative에서 처리 (positive에서 약화시키지 말 것)

## 3. Negative 프롬프트 작성 규칙

### 3.1 필수 포함 항목
```
worst quality, low quality, bad anatomy, bad proportions, bad hands, extra fingers, missing fingers, mutated hands, extra limbs, deformed, jpeg artifacts, watermark, signature, text
```

### 3.2 성별 배제 (gender-specific)
- **여성 캐릭터**: `1boy, male, masculine, beard, mustache, facial hair`
- **남성 캐릭터**: `1girl, female, feminine, breasts, cleavage`

### 3.3 스타일 배제
```
photorealistic, realistic, 3d, render, cgi, flat color, thick lineart, paint, body paint, stains, smudge, colored skin
```

### 3.4 레이아웃 배제 (단일 이미지 보장)
```
(multiple views:1.5), (comic:1.5), (panel layout:1.4), (speech bubble:1.4), (text box:1.3), (split screen:1.4), border, frame, monochrome, greyscale
```

### 3.5 캐릭터별 색상/특징 고정
- **머리 색상 고정 예시** (검은 머리 캐릭터):
  ```
  ((pink hair, purple hair, red hair, blonde hair, brown hair, silver hair, white hair, blue hair, green hair, colored hair:1.5))
  ```
- **의상 색상 고정 예시** (분홍 드레스 캐릭터):
  ```
  ((purple dress, black dress, blue dress, white dress, red dress, dark dress:1.5))
  ```
- **헤어스타일 고정 예시** (단일 쪽진 머리):
  ```
  ((double bun, two buns, twin buns, odango, twintails, twin braids, pigtails, multiple hair buns:1.5))
  ```

### 3.6 Negative 강도 조절
- 절대 나오면 안 되는 요소: `(표현:1.5)` 이상
- 일반적인 배제: 가중치 없음 (기본값 1.0)
- 약한 배제: `(표현:0.8)` (드물게 사용)

## 4. 실전 체크리스트

### 생성 전 확인사항
- [ ] `sdxl_positive`와 `sdxl_negative` 필드 존재
- [ ] Positive에 BREAK 구분자로 섹션 분리
- [ ] Positive에 퀄리티 태그 포함
- [ ] 피부 색상 표현이 중립적 (`clean pale skin`, `fair skin`)
- [ ] Negative에 기본 퀄리티 배제 태그 포함
- [ ] Negative에 성별 배제 태그 포함
- [ ] Negative에 원하지 않는 머리색/의상색 명시 (높은 가중치)
- [ ] Negative에 레이아웃 배제 태그 포함
- [ ] `ref_weight` 값 설정 (권장: 0.75)

### 체크포인트 간 테스트
```bash
# 최소 3개 체크포인트로 동일 포즈 비교 테스트
python flux_batch_generator.py -c [캐릭터] -p 037 --engine sdxl --ckpt "unholyDesireMixSinister_v90.safetensors" --ckpt-tag unholy
python flux_batch_generator.py -c [캐릭터] -p 037 --engine sdxl --ckpt "waiIllustriousSDXL_v170.safetensors" --ckpt-tag wai
python flux_batch_generator.py -c [캐릭터] -p 037 --engine sdxl --ckpt "HEXMIX_V2.safetensors" --ckpt-tag hexmix
```

**판정 기준:**
- 색상 일관성: 주황빛/초록빛 틴트 없어야 함
- 캐릭터 일관성: 머리색, 의상색, 헤어스타일 동일해야 함
- 해부학적 정확성: 손가락, 팔다리 수 정상
- 단일 인물: 추가 인물 등장 없어야 함

## 5. 사례 연구: sample_character 문제 분석

### 문제가 있던 구조 (BAD ❌)
```json
{
  "appearance": {
    "face_and_hair": "..., luminous warm amber eyes, gentle healthy skin tone",
    "physique": "slender waist, soft feminine curves",
    "outfit": "..."
  },
  "style_keywords": "cinematic anime digital artwork, subtle depth of field, exquisite fabric textures, masterpiece quality, 8k resolution"
}
```

### 문제점
1. **`sdxl_positive`, `sdxl_negative` 필드 부재** → 엔진별 최적화 불가
2. **"gentle healthy skin tone"** → WAI/HEXMIX에서 주황빛으로 오해석
3. **Negative 프롬프트 전무** → 색상 오염, 다중 인물 등장, 해부학적 오류 방지 불가
4. **`style_keywords` 별도 필드** → 프롬프트 빌더 처리 방식 불명확, 중복 가능성

### 개선된 구조 (GOOD ✅)
```json
{
  "appearance": { "...": "(레거시 호환용)" },
  "sdxl_positive": "masterpiece, best quality, newest, absurdres, aesthetic illustration, delicate anime coloring, soft shaded skin, finely detailed beautiful eyes BREAK 1girl, solo, slender waist, soft feminine curves, graceful posture BREAK dark chestnut brown hair in neat ponytail, luminous warm amber eyes, refined facial features, clean pale skin BREAK pristine fitted white blouse, beige tailored jacket, matching pleated short skirt",
  "sdxl_negative": "worst quality, low quality, bad anatomy, bad proportions, bad hands, extra fingers, missing fingers, mutated hands, extra limbs, deformed, jpeg artifacts, watermark, signature, text, 1boy, male, masculine, beard, mustache, facial hair, photorealistic, realistic, 3d, render, cgi, flat color, thick lineart, (multiple views:1.5), (comic:1.5), border, frame",
  "ref_weight": 0.75
}
```

### 결과
- ✅ 모든 체크포인트에서 색상 일관성 유지
- ✅ 주황빛/초록빛 틴트 제거
- ✅ 단일 인물 보장
- ✅ 해부학적 정확성 향상
