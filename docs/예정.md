## 1. 코랩 원격 ComfyUI 연동 (SDXL 생성 분담)

- **상태**: 예정 (설계 완료, 구현 미착수)
- **목표**: 로컬 4060 Ti 8GB의 VRAM 병목 해소. SDXL 이미지 생성만 코랩(T4 16GB → Pro A100)에 맡기고, QC·검열은 로컬 유지.
- **분담 경계**:
  - 코랩: SDXL KSampler 생성 + Face Detailer (ComfyUI 워크플로우 노드)
  - 로컬: Auto-QC 4대 감지기(`qa_validator.py`) + 실루엣 검열(`censor.py`, MobileSAM/imgutils)
- **연결 방식**: ngrok 무료 고정 도메인 (https/wss). 모델은 구글 드라이브 마운트로 재사용.
- **주요 변경 산출물**:
  - 신규: `plepa_engine/comfy_urls.py` (스킴 해석 헬퍼), `colab/plepa_colab_sdxl.ipynb`, `docs/COLAB_SETUP_GUIDE.md`
  - 수정: `plepa_engine/config.py`, `plepa_engine/comfy_client.py`, `plepa_engine/services/config_service.py` (스킴 통일 + ngrok 호환 헤더)
- **리스크 / 우선순위**:
  - (최우선) Task 2-3 로컬 하위호환 보장 — 기존 pytest 57종 회귀 필수 통과. 깨지면 플에파 전체 정지.
  - (고위험) Task 5 ngrok 무료 고정 도메인 클레임 가능 여부 검증 — 불가 시 `trycloudflare` 폴백.
  - (투자 판단) Task 6 T4 실제 성능 측정 후 Pro(A100) Go/No-Go 결정 — 데이터 없이 Pro 결제 위험.
- **의사결정**: 플에파 내부에서 진행(별도 프로젝트 분리 안 함), 브랜치 `feature/colab-remote`.
- **Task 분해**: 7단계 — (1) 스킴 헬퍼+테스트 → (2) 3곳 연동+하위호환 → (3) 목 서버 통합 테스트 → (4) 코랩 환경 구축 → (5) ngrok 터널 → (6) E2E 라이브 검증 → (7) 운영 문서.
- **만일의 탈출구**: 효율 안 나오면 `comfy_host` 원복 즉시 롤백 / ngrok 불가 시 폴백 / 네트워크 병목 시 "업스케일만 코랩" 부분 축소.
- **상세 설계서**: [docs/COLAB_REMOTE_PLAN.md](./COLAB_REMOTE_PLAN.md) (10섹션 + 완성도 평가·리스크 분석·프로젝트 분리 검토 포함)
